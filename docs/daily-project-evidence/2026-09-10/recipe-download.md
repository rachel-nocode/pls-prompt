# Revision Lens

Compare two drafts. See exact additions and removals. Keep the context.

Recipe version: daily-revision-lens-v1
Tool: Codex · GPT-6 Astra (High)

## Before you start

Open an empty folder in Codex. Paste Step 1, then Step 2 in the same task. Open revision-lens.html in a modern browser, or serve it with a static server. No packages, accounts, keys, images or paid services are required. PLS PROMPT supplies separate gallery framing and the recipe download.

## 1. Build Revision Lens

Build revision-lens.html: a complete standalone text comparison mini app using inline HTML/CSS/JavaScript, no packages, assets, network, storage, accounts, payments, eval or form submission. Include viewport meta and CSP default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; connect-src 'none'. It runs inside an opaque iframe sandbox='allow-scripts'; send parent.postMessage({type:'pls-demo-ready'}, '*') after initialization.

Design an ASCII Atelier editorial instrument. Near-black #080808 canvas, #111111 surfaces, #383838 panel lines, #777777 control borders, #f2f2f2 main and #b8b8b8 secondary text. Large condensed system-sans REVISION LENS heading, monospace interface, restrained decorative ASCII +---+ separator. Subtitle: See what changed. Keep the context. Desktop two columns: stacked Before/After editors left, comparison ledger right; stack below 760px. Use mint #a8ebcb only for added content, pale rose #f5b2ba only for removed content, neutral unchanged content; explicit Added/Removed/Unchanged labels, plus/minus/equal signs and removed text strikethrough prevent color-only meaning. No animation or audio. Labels >=.875rem, body 1rem, native fields 1rem, all targets >=44px, clear focus, neutral controls, content wraps even for a 6,000-character unbroken string, no page horizontal overflow at 320/375/768/1024/1440/1600px and 200% root font at 320px.

Initial committed comparison uses Word mode, Before='Build small. Test often. Ship with care.' and After='Build small. Test early. Ship with confidence.'. Provide visible labeled textareas Before and After, a Comparison unit select Word/Line, Compare texts primary button, Swap inputs, Clear texts, Reset workshop, and two preset buttons Editorial and Packing list. Word mode splits trimmed input by Unicode whitespace (empty/whitespace-only -> []); punctuation stays attached to its word; original spacing is intentionally normalized and differences in whitespace alone ignored. Comparison is case-sensitive, no spelling or semantic inference. Line mode normalizes CRLF and lone CR to LF, then splits on LF, preserving blank lines and terminal newline as an empty final unit; exactly empty string is []; whitespace-only line is a real unit. Limits: each raw input <=6,000 JavaScript UTF-16 code units (label as 6,000-character input cap and disclose UTF-16 in limits), each normalized input <=200 units. Do not truncate input, enforce textarea maxlength, silently switch modes, or treat empty input as invalid.

Compare uses dynamic programming to compute a longest common subsequence of units. Suffix matrix (lenA+1)*(lenB+1); equal tokens match, otherwise max of delete/insert successors. Backtrack deterministically, taking deletion from Before first when successor scores tie. Operations equal/remove/add must reconstruct each normalized input and minimize added+removed units; consecutive operations of same kind merge into runs. Counts are units, not runs: initial unchanged=5, removed=2, added=2; initial before/after totals=7. No misleading similarity score. Show all five counts and the committed mode. Render runs in original diff order with type label and unit count plus text; Word runs join by a single space, Line runs show individual lines (blank lines visibly marked '(empty line)', whitespace-only lines visibly marked '(whitespace line)' while report retains their original spaces). Use textContent/createTextNode/value only for user text, never innerHTML. Show 'No differences.' when input sequences equal, including whitespace-only differences in Word mode; show 'Both texts are empty.' for two empty sequences. An accessible Changes only checkbox filters equal runs without changing counts or report; when no changed units exist, show 'No changed units to show.' alongside the equality status. Unchecking restores context. This filter persists across Compare, Swap inputs and Clear texts; presets and Reset restore unchecked.

Editing input or mode updates a visible 'Inputs changed. Compare to refresh.' notice and leaves committed counts, runs, mode and report unchanged. Compare validates both inputs atomically: too many characters/units shows polite readable error and aria-invalid on offending textarea, retains full input and previous result/report, and keeps a pending indicator. A successful Compare clears errors/pending and commits the current values/mode even for empty inputs. Clear stale errors when editing the relevant textarea. Swap inputs swaps raw textarea values and marks pending, preserving previous result until Compare. Clear texts empties both editors and immediately commits empty results in current mode. Editorial immediately restores initial texts/Word mode and compares. Packing list immediately uses Line mode with Before='Passport\nCamera\nNotebook\nCharger' and After='Passport\nNotebook\nHeadphones\nCharger', producing kept3/removed1/added1. Reset workshop restores Editorial and unchecked filter. Keep button focus through renders.

Include a read-only labeled Comparison report textarea updated only after valid commits; independent of Changes only and pending edits. Report contains title Revision Lens v1, committed mode, Word/Line normalization note, counts and ALL operations. Encode each unit as JSON string on its own line prefixed '= ', '- ' or '+ ' (therefore tabs, backslashes, newlines and empty units are unambiguous); normalized input sequences must be recoverable by reading '='/'-' for Before and '='/'+' for After. Select report focuses/selects it. Copy report tries guarded navigator.clipboard.writeText then guarded document.execCommand('copy'); 'Copied' only on actual success, otherwise explain Select report/manual browser copy. Fallback restores Copy button focus. Polite live status for explicit actions only, not every keystroke or diff token. No demo download inside sandbox; host supplies separate recipe download.

Visible limitations: Local session only. Exact text comparison, not semantic review. Word mode ignores whitespace and keeps punctuation attached. Case-sensitive. At most 200 units and 6,000 characters per input. No uploads, persistence, automatic AI rewriting or external services. Treat CR normalization and UTF-16 character counting honestly in expanded limits. Use fresh minimal implementation, not a library.

## 2. Verify and repair

Verify and repair Revision Lens in a real Chromium browser within iframe sandbox='allow-scripts' and exact CSP. Check initial counts 5 unchanged/2 removed/2 added and totals 7/7; packing sample 3/1/1. Validate LCS minimal edits and operation reconstruction against an independent prefix-DP edit-distance oracle over exhaustive pairs of short sequences from a small alphabet. Check deletion-first ties with Before='A B', After='B A'. Test empty/identical, additions-only, removals-only, repeated units, case and punctuation, Word whitespace normalization, Line blank/whitespace-only/terminal newline and CR normalization. Test literal HTML/script-like input renders harmlessly. Exactly 200 units and 6,000 UTF-16 units allowed; 201/6,001 refused atomically without truncation or changes to prior output/report. Inputs and mode remain pending until Compare; errors clear appropriately; Swap stages only; Clear commits empty in current mode; presets/reset replace pending text and restore filter. Changes only never changes counts/report. Parse JSON report operations to reconstruct both normalized inputs, test full selection and injected clipboard success/failure with focus restoration. Confirm keyboard actions, six viewport widths, 200% root text at 320, touch emulation, reduced motion, null-origin readiness, storage denied, zero external requests and no script errors. Capture real initial and line-mode previews. Repair issues and report actual checks and interventions, with no unsupported cross-browser/accessibility or one-shot claims. Separately rebuild from these two prompts in an empty directory without original source or screenshots, then repeat functional tests and honestly record differences and failures. Gallery hosting and recipe download are separate integration, not generated by this standalone prompt.

## Make it yours

Change the sample drafts, typography or data colors while keeping explicit Added/Removed/Unchanged labels. Add a comparison unit only with a documented normalization rule and reversible report. Raising input limits requires revisiting the quadratic comparison cost and browser rendering limits.

## Known limits

Session only. Exact case-sensitive text comparison, not semantic review or AI rewriting. Word mode ignores whitespace and keeps punctuation attached; Line mode normalizes CRLF/CR and preserves blank or terminal lines. Each input allows 200 units and 6,000 UTF-16 code units; some characters use two code units. No uploads, storage or external services. Clipboard may be denied; Select report supports manual copying. Consolidated build/verification pack, not a verbatim transcript or one-shot guarantee. Behavioral reproduction, not identical pixels. Chromium only; touch emulated and clipboard branches injected. No Safari, physical-device, screen-reader or independent-human testing.
